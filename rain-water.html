11. Container With Most Water

为什么移动短边？

area = min(left, right) × width
  • 保持短边不动、移动长边 → min() 不变或减小，width 减小 → 面积只会更小
  • 因此短边这一侧的所有组合可以安全丢弃
  • 移动短边才有机会遇到更高的柱子，找到更大面积
  • 两边相等时移动哪边都可以，原因相同
暴力 O(n²)
双指针 O(n)

42. Trapping Rain Water

每个位置能接多少水？

water[i] = min(left_max, right_max) - height[i]
  • 接水高度取决于左右两侧最高柱子中较矮的那个
  • 高度相等时水会从两侧漏走，所以是严格的 min()
  • 接不到水时结果 ≤ 0，直接累加不影响答案
  • 需要提前知道每个 i 的左最大值和右最大值
预处理法 时间 O(n)
空间 O(n)

算法思路

为什么需要三趟遍历？

  • 计算 water[i] 需要同时知道左最大值和右最大值
  • 从左往右遍历时，走到 i 还没见过右边的数据 → 无法当场得到右最大值
  • 解决方案：提前用两趟遍历把所有信息存入数组，第三趟直接查表
# 第一趟：从左往右建 pre_max for i in range(1, n): pre_max[i] = max(pre_max[i-1], height[i]) # 第二趟：从右往左建 suf_max for i in range(n-2, -1, -1): suf_max[i] = max(suf_max[i+1], height[i]) # 第三趟：查表累加 for pre, suf, h in zip(pre_max, suf_max, height): ans += min(pre, suf) - h

range() 从右往左

range(start, stop, step)

  • step = -1 代表往左走
  • stop 是不包含的，想到达 0 就写 -1
  • 想到达 1 就写 0，以此类推
# 从 n-2 遍历到 0（包含） range(n-2, -1, -1) # 从 n-2 遍历到 2（包含） range(n-2, 1, -1)
口诀：stop 比你想到达的终点再多往左走一步

负数 index vs range stop

⚠️ 两个 -1，两种含义

  • height[-1] → 数组最右边的元素（index用法）
  • range(n, -1, -1) 里的 -1 → 遍历边界，代表"到0为止"
易混淆！ 同样是 -1，在 index 里是最后一个元素，在 range 里只是停止条件的边界值。

zip()

多数组同位置同时遍历

  • 把多个数组按位置打包，每次取出同一位置的元素
  • 比手写 for i in range(n) 再取 [i] 更简洁
for pre, suf, h in zip(pre_max, suf_max, height): # 等价于： # pre = pre_max[i] # suf = suf_max[i] # h = height[i]

数组初始化

[0] * n vs [] * n

  • [0] * n → 长度为 n、每格填 0 的数组 ✅
  • [] * n → 还是空数组 []，无法用 index 赋值 ❌
pre_max = [0] * n # ✅ 正确 pre_max[0] = height[0] # 初始化边界

Bug 1

for loop 起点错误

建 pre_max 时，loop 从 range(0, n) 开始，当 i=0 时访问 pre_max[-1]（Python 的最后一个元素），产生错误结果。

正确做法： 初始化 pre_max[0] = height[0]，loop 从 range(1, n) 开始。
Bug 2
suf_max = height[n-1] 和 suf_max[n-1] = height[n-1] 有什么区别？
点击查看答案 →
Bug 2

把数组赋值成数字

写 suf_max = height[n-1] 会把整个 suf_max 数组覆盖成一个数字，之后无法用 index 访问。

正确做法： suf_max[n-1] = height[n-1]，只修改最后一格。
Bug 3
建 suf_max 时，loop 从 range(n, ...) 开始会怎样？正确起点？

Bug 3

range 的 start 越界

建 suf_max 时，loop 从 range(n, ...) 开始，访问 height[n]，index 越界报错。

正确做法： 最后一格已初始化，loop 从 range(n-2, -1, -1) 开始。
Bug 4
第三趟 ans += 写在 for loop 外面会发生什么？
点击查看答案 →
Bug 4

for loop 写在外面

第三趟计算接水量时，ans += 写在 for loop 外面，只计算了最后一个 i 的值，其余全部丢失。

注意缩进： 累加逻辑必须在 for loop 内部。

核心本质

为什么双指针能把 O(n²) 降到 O(n)？

1
每一步用 O(1) 的代价，安全排除一批不可能是最优解的组合
2
"安全"的依据：min() 不变或减小 + width 只减不增 → 被丢弃的组合面积一定更小
3
从两端出发保证覆盖最大宽度，每次移动短边保证不漏掉最优解
这个分析框架可以迁移到其他双指针题：先找公式，分析哪一侧可以安全丢弃，从两端出发。
